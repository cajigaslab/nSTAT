## 4. Phase F2 — Name-value `fromStructure` refactor (this repo, optional polish)

### F2.1 — Scope decision

`TrialConfig.fromStructure` is the file that produced bugs #19 and #58. The `methods (Static)` block at `TrialConfig.m:159` currently uses positional args. Refactor:

```matlab
function tcObj = fromStructure(structure)
    tcObj = TrialConfig( ...
        structure.covMask, ...
        structure.sampleRate, ...
        structure.history, ...
        structure.ensCovHist, ...
        structure.ensCovMask, ...
        structure.covLag, ...
        structure.name);
end
```

The cleanest refactor is to add a name-value `inputParser` to the `TrialConfig` constructor and dispatch — but that's a **public API change** that touches every caller. Out of scope.

**Recommend a smaller change**: keep the constructor positional, but introduce a defensive comment block above `fromStructure` listing the constructor's positional order. The bug was a maintainer reading the constructor signature wrong; documentation at the read site is the minimum-invasive fix.

```matlab
methods (Static)
    function tcObj = fromStructure(structure)
        % NOTE: TrialConfig constructor signature is
        %   TrialConfig(covMask, sampleRate, history, ensCovHist,
        %               ensCovMask, covLag, name)
        % Any addition of a new positional argument MUST update this
        % call in lockstep. Issues #19 and #58 happened because the
        % constructor's positional list silently grew while this method
        % did not.
        tcObj = TrialConfig( ...
            structure.covMask, ...
            structure.sampleRate, ...
            structure.history, ...
            structure.ensCovHist, ...
            structure.ensCovMask, ...
            structure.covLag, ...
            structure.name);
    end
end
```
